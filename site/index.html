Pipeline

How it works

Five-stage pipeline from topic input to verified, evidence-grounded MCQ output.

1

Configure topic & competency

Define the medical topic (e.g. "Hypertension") and learning competency. Set how many questions to generate per topic.

Next.js UI
2

Retrieve evidence

BM25 sparse retrieval combines with MedCPT dense reranking to pull the most relevant passages from PubMed articles and medical textbooks. Falls back to live PubMed Web API when the local corpus returns no results.

BM25 + MedCPT Hybrid
3

LLM generates candidates

Retrieved evidence is injected into a structured prompt. An LLM (Gemini, Groq, Cerebras, or any OpenAI-compatible provider) generates multiple MCQ candidates in a single call.

RAG Prompting
4

Cross-CoVe verification

Three independent reviewer LLMs each evaluate every candidate for evidence support, clinical accuracy, and option quality. The question passes only when a majority agrees it is correct.

Chain-of-Verification · Majority Vote
5

Export & review

Verified questions are displayed with full evidence provenance. Export as JSON, print-ready PDF, or editable DOCX. Switch between English and Indonesian output on the fly.

JSON · PDF · DOCX
Features

Built for clinical accuracy

Every design decision prioritizes evidence grounding and verifiability over raw generation speed.

Hybrid RAG Retrieval

Combines BM25 sparse retrieval with MedCPT neural reranking to surface the most clinically relevant evidence passages from a curated corpus.

BM25 + MedCPT

Cross-CoVe Verification

Chain-of-Verification with three independent reviewer LLMs. A question only passes when a majority of reviewers validate it against the retrieved evidence.

Majority Voting · 3 Reviewers

Multi-Provider LLM

Plug in any provider — Gemini, Groq, Cerebras, OpenAI-compatible API, or Ollama for local inference. Generator and reviewers can each use different providers.

Gemini · Groq · Cerebras · Ollama

Multi-Format Export

Export your verified question set as raw JSON for downstream processing, a print-ready PDF exam sheet, or an editable DOCX document.

JSON · PDF · DOCX

Multilingual Output

Generate questions natively in English or Indonesian. Switch display language on the history page without re-generating — output is stored in both languages.

English · Indonesian

Generation History

Every run is stored locally with full provenance: evidence doc IDs, verification reports, per-attempt latency, and failure reasons for each question.

Local Storage · Audit Log
Architecture

System overview

↕

Verification Layer

CrossCoVeReviewer · ReviewerClient · gate.py

Streaming pipeline

The backend streams question events over SSE as they are generated, so the UI updates in real time without waiting for the full batch to complete.

OK-only mode

When enabled, the pipeline retries generation until a question passes Cross-CoVe, falls back to the question bank if max rounds are exhausted, and never surfaces a failed question to the user.

Pluggable LLM abstraction

LLMClient routes to provider-specific adapters (Ollama, Groq, Cerebras, Gemini, OpenAI-compatible) with configurable fallback chains, so swapping providers requires only a .env change.

Latency audit logging

Every run records per-attempt retrieval, LLM, and verification latency to JSONL and CSV for performance analysis.
